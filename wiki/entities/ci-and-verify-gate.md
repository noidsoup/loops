# CI and the verify gate

Two gates check the same suite: `npm run verify` locally (the agent's "done" gate) and GitHub Actions on push and PR.

## What runs

| Gate | Steps | Source |
|---|---|---|
| `npm run verify` | `node adapters/emit.js --check`, then `npm test` | `.verify.sh` |
| `npm test` | `node --test test/*.test.js`, then `node adapters/emit.js --check` | `package.json` |
| CI | `npm test` on Node 20 (`ubuntu-latest`), push to `main` and every PR | `.github/workflows/ci.yml` |

## Why the drift check comes first

`test/emit.test.js` re-emits into the working tree. By the time `npm test` reaches its own `emit --check`, the files already match, so that check can never fail. `.verify.sh` checks drift before the tests for this reason (commit `cc18520`). CI has the same blind spot: it runs `npm test` only.

## What the tests guard

Test files in `test/` cover: dispatcher coverage of every loop, persona coverage, the `loop.yaml` schema, the self-correcting contract, model-class resolution and banned names, emit and install-global units. Coverage grew from 13 to 120 tests in commit `3106f9e` and was 149 at commit `cc18520`.

`.verify.sh` is generated by a machine-level script (header comment) and exits 1 when a repo has no runnable checks, so a missing gate never looks like a pass.
